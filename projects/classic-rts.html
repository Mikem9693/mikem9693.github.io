Classic RTS: Red Alert 1 in browser

An unofficial browser version of Red Alert. Play it here

The Project

Red Alert is a game I remember fondly from my childhood, EA releasing it as freeware in 2008 made it an ideal learning project.

Browser versions of Red Alert existed already,so I tested two. The first used DOS emulation and stuttered badly. The second ran the engine in browser directly but any switch away from the game froze the tab. I traced the freeze to the original code which assumed control of the whole machine and waits inside its own loops, never handing control back to the browser.

This presented the fist test of viability and became the first acceptance test: switching tabs, resizing the window or opening dev tools must not freeze the game.

My role

I ran this as product owner and delivery lead, with an AI coding assistant (Claude Code) as the engineer. I split the work into phases with clear gates. Each ticket had a goal, files in scope, constraints and acceptance tests. I reviewed every plan before approving it and every diff before committing it. When there was something I didn't understand, I researched or asked a separate AI chat to explain it. The aim was to learn, not just letting AI develop.

Licensing, security, privacy, hosting and release timing were my decisions, and I recorded the reasoning for each. I also ran the release: setting up hosting, uploading game data and deploying each version, tagged in Git so it links to its exact source code.

Using Fable 5.2 to instruct agents using less powerful models to complete development work reduced costs by around 50% with no visible drop in quality

What I built

A working version of Red Alert built from open-source Vanilla Conquer engine, compiled to WebAssembly with Emscripten

Skirmish & private multiplayer
Play against the AI in a one off battle, or play against friends in a private room from a shared link. Browser connections (WebSockets) replaced the games single networking interface.
94% smaller download
Game data reduced from 480Mb to 28Mb skirmish only pack.
No freezing
Emscripten’s Asyncify feature makes the game’s waits hand control back to the browser. Switching tabs, resizing or opening developer tools no longer freezes the game.
Security and privacy
Strict Content Security Policy, a relay that only accepts the real site and limits connections and message sizes, and cookieless analytics that store no personal data.
Small footprint
Changes kept to a minimum with only 15 file changes and 798 lines added

Where review matted

Choosing the project
I rejected my first idea, Red Alert 2, because it failed on feasibility, licensing and verifiability.
A 1996 bug
A game crashing bug was discovered when testing. This was identified as a result of a unit being used after being destroyed by an exploding crate. A two line fix was applied with no reoccurrences
Security gap
Reviewing the relay's deployment plan the AI flagged that the per-address limit trusted a fakeable. I made the fix a condition of approval

Outcome

Publicly playable
Skirmish and private multiplayer at classic-rts.pages.dev.
Ahead of plan
Intial plan outlined for 15 weeks. First release within six days of project start
Tested
48 automated relay tests passing at release, plus browser checks of every security policy.
A complete audit trail
Every phase recorded in commits, tags, a changelog and session notes, including what the AI got wrong and how it was caught.
Troubleshooting
Some instances resulted in the game crashing after deployment of MCV and remaining frozen until connection dropped. This was identified as an issue with the relay server being classified as a trial account. This caused server to shut down after around five active minutes.

What I learned

Managing AI delivery
Writing tickets an AI can execute well, using plan-first workflows, reviewing diffs instead of trusting output, and matching model and cost to task difficulty.
Delivery discipline with AI
Phase gates; change control when an assumption proves wrong; isolating variables when diagnosing problems; regression testing; and structuring development to stay within usage limits.
Technical foundations
Linux and WSL; Git workflows, including branches, merging diverged histories, tags and releases; CMake and C++ builds; WebAssembly and the browser event loop.
Responsible open source
GPL obligations, keeping copyrighted assets out of public code, trademark limits, privacy by design, and the etiquette of contributing upstream.
Agentic AI
Understanding when and how to use more powerful models and how to instruct to limit token spend.
